feat(positions): job position catalogue

Ticket 08, first half. The role-assignment half needs a users table, which
arrives with ticket 09, so it moves to 08b; the catalogue depends only on
departments and assignments and is complete here.

- Position CRUD under a department, with a managerial flag that later derives
  the manager role.
- A code is unique within its department, not globally: codes describe a role
  inside a team, so `manager` legitimately exists under several departments. A
  partial unique index enforces it in the database as well.
- A position is never hard-deleted while anything references it. Deactivation is
  the supported way to retire a role: existing assignments keep resolving, new
  ones are refused (the employee path already rejects an inactive position).
- The catalogue list reports both counts in one query rather than an N+1 loop:
  live assignments, which is what an operator looks for, and total references,
  which is what blocks deletion.

Also fixed: deletion was decided on active assignments alone, but
`employee_assignments.job_position_id` is RESTRICT. A position referenced only
by history passed the check and then failed inside the database, turning a clear
409 into a 500. It now counts every reference.

Probes: probe_positions covers 20 checks over real HTTP, and every probe now
asserts it left no rows behind — an earlier version of probe_employees leaked
department rows because it deleted employees before the departments that
reference them.
