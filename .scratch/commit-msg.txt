feat(employee): records, private details, multi-position assignments

Ticket 07. Adds the people the rest of the system is about, and puts the
visibility line the ticket draws into a single testable rule.

- Two tables for one person: `employees` holds what the directory may read,
  `employee_private` holds what only the person, HR, finance and compliance may
  read. Withholding the address becomes a property of the query rather than
  something every call site must remember.
- `employee_assignments` carries the position history that lets one person hold
  several positions across departments, with the approver per position and a
  fallback to the department manager resolved at the edge.
- The first assignment becomes primary by construction; a client cannot ask for
  the flag, and promoting another position is an administrative endpoint. A
  partial unique index keeps at most one active primary per person.
- Ending the last active position is refused: every later feature assumes an
  employed person has somewhere to be.
- `domain/employee/visibility.py` decides what a viewer receives, as a pure
  function with an exhaustive viewer-by-field-group matrix test. The transport
  layer never guesses which fields to serialise.
- Withheld fields are absent from the payload, never null, so a client cannot
  read "not allowed to know" as "not recorded".
- `departments.manager_employee_id` finally gets its foreign key, deferred from
  revision 0002 which had no employees table to point at.

The ticket requires that ID numbers, bank details, health data and biometrics
are not stored. A CHECK constraint cannot express that (PostgreSQL rejects
subqueries inside CHECK), so migration 0003 installs a DDL event trigger that
refuses any ALTER TABLE adding such a column, and a test drives the trigger to
prove it fires. Request schemas use extra="forbid" so a client sending a
national_id gets 422 instead of a 201 and a silent drop.

Also fixed while verifying: withheld fields reappearing as null because the
response model serialised its own defaults; the directory projection emitting
"email": null for withheld rows; and an in-memory substitute missing the patch
helper the service had started to use.
