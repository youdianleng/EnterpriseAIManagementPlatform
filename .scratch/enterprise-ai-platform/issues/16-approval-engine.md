# 16 — 审批引擎内核与状态机

**What to build:** 一个所有单据共用的审批引擎：任何东西提交后都走直属经理 → 人力资源两级。经理可以通过、驳回或退回补正；退回后申请人可修改再提交，且此前的决定记录全部保留。引擎不关心单据内容，只负责流转。

**结构约束:** 接口固定为 `submit` / `decide` / `withdraw` / `state_of` 四个操作（`docs/architecture/codebase-design.md` §2.3）。**"生效"不属于引擎**——引擎只回答"批没批"，生效由各领域模块自己的定时任务读取"已批准且到期"的单据执行。把生效逻辑塞进引擎会让引擎必须理解每种单据的字段语义，深度立刻崩塌。

**Blocked by:** 15 — 权限矩阵与越权测试套件

**Status:** ready-for-agent

- [ ] 状态机固定为：草稿 → 待一级（直属经理）→ 待二级（人力资源）→ 已通过；另有已驳回与已撤销两个终态
- [ ] 支持三种决定：通过、驳回、退回补正；退回补正使单据回到草稿且历史决定保留可查
- [ ] 审批上级取自申请人**主职位**对应的审批上级；未配置时回退到该部门负责人
- [ ] 第一级审批人与第二级审批人为同一人时，不得自我审批同一张单据（自动跳过或要求他人代审，行为需明确且被测）
- [ ] 申请人可在进入第二级之前撤销单据
- [ ] 每次决定记录审批人、决定、意见、时间；记录为追加式，不可修改
- [ ] 引擎以统一的实体类型 + 实体 ID 关联任意业务单据，新增单据类型不需要改动引擎（用一张演示用的假单据类型验证这一点）
- [ ] 全部状态流转路径有测试覆盖，含退回后重新提交、驳回后不可再提交、越权审批被拒
