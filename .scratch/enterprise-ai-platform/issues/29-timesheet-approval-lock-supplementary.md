# 29 — 审批锁定、补充提交与周锁

**What to build:** 工时表审批通过后**永久锁定**，任何人都不能直接改。要修正只能发起"补充提交"：系统生成与原条目配对的冲销记录（负值）加新条目，净额正确而原始记录一字不动。补填只允许回溯最近 8 周。

**Blocked by:** 28 — 周工时表录入与提交；16 — 审批引擎内核与状态机

**Status:** ready-for-agent

- [ ] 工时表走两级审批（直属经理 → 人力资源），复用统一审批引擎
- [ ] 审批通过后状态变为已锁定，无法直接编辑任何条目
- [ ] 对已锁定的周发起补充提交时，系统生成一张关联原工时表的新工时表
- [ ] 补充提交中，被修改的原条目对应生成类型为"冲销"的负值条目，同时写入新的正值条目
- [ ] 原工时表与新工时表之间的关联双向可查；原始记录永久保留且可追溯
- [ ] 补充提交同样走两级审批，通过后净额正确（用测试断言：原 + 冲销 + 新增 = 期望值）
- [ ] 补填窗口为最近 8 周，超出窗口的周被拒绝并给出可读的西/英提示与剩余可补周数
- [ ] 全局周锁机制存在：超出补填窗口的周不但不可补填，任何写入路径都无法触及
- [ ] 界面上能直观看到哪些周已锁定、哪些周仍在补填窗口内
