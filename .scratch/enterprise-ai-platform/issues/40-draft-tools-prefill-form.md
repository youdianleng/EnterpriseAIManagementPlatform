# 40 — 草稿工具：产出待确认表单（不写库）

**What to build:** 员工说"帮我请下周三的假"，助手不是直接提交，而是**生成一张填好的请假表单**展示给员工看。助手在整个系统里根本没有写数据库的能力——这不是靠提示词约束，而是代码结构上不存在这样的工具。

**结构约束:** 落实 `docs/architecture/codebase-design.md` 约束 B 的第 1 层——`ai/**` 不得 import 任何写入型仓储，且 `domain/` 不得被 `ai/` 反向依赖（约束 A）。测试断言 AI 可触达的工具集合中不存在写库工具。

**Blocked by:** 39 — 只读工具（本人 + 经理）；16 — 审批引擎内核与状态机

**Status:** ready-for-agent

- [ ] 提供草稿工具：请假申请草稿、补打卡草稿、工时表草稿
- [ ] 草稿工具只**构造并返回**一张结构化表单，不产生任何数据库写入
- [ ] 草稿内容经过校验：日期范围、额度是否足够、项目任务是否存在、格式是否合法；不合法时明确告知原因而不是生成一张注定失败的草稿
- [ ] 草稿以持久化状态保存并关联到对话，刷新页面或重启服务后仍能找到未确认的草稿
- [ ] 草稿有有效期（默认 24 小时），过期后标记为失效并要求重新生成
- [ ] 架构层面验证：AI 模块的依赖中**不存在**任何写入型仓储；有一条测试断言助手可调用的工具集合里没有任何写库工具
- [ ] 草稿内容在界面上以完整可编辑表单呈现，员工可以在提交前修改任何字段
