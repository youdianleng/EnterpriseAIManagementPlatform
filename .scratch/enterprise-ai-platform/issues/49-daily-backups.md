# 49 — 每日数据库与文档卷备份（7 天保留，可关闭）

**What to build:** `docs/DESIGN.md` D33 的部署决策写得具体：*每日 `pg_dump` + 文档卷 rsync，保留 7 天，可通过环境变量关闭*（§10 备份行）。仓库里目前**没有**任何实现——`pg_dump` 只出现在设计文档里。这条是设计文档的明确要求而没有归属票据，本票补上，并且要能让"备份可用"这件事被验证，而不是只写一段说明。

**Blocked by:** 04 — 数据库迁移、pgvector 与 Redis 接入（Compose 与卷的既有形状）

**Status:** ready-for-agent

- [ ] 备份进程作为 Compose 的一个服务存在（与 api/web/postgres/redis 并列），按日执行 `pg_dump`（自定义格式，便于选择性恢复），并把文档存储卷同步到同一个备份卷
- [ ] 保留 **7 天**：超过 7 天的备份被删除；保留天数可配置（默认 7）
- [ ] 可通过环境变量关闭（默认开启或默认关闭由实现决定，但必须**写明**并在 README 里给出开关名）
- [ ] 备份**不**把密码写进命令行或日志；凭据来自既有的 Compose 环境变量
- [ ] **恢复步骤写进 README**：一个新库如何从备份恢复、恢复后如何跑迁移校验
- [ ] 有一个探针（`api/tests/tools/`）或脚本，证明产出的备份是**可恢复的**：把最新备份恢复到一个临时 scratch 数据库，断言关键表非空或 `alembic_version` 与 head 一致，然后删掉临时库。只证明"文件存在"不算验证
- [ ] 备份失败必须可见：进程非零退出、结构化日志一行说明原因（D30 的日志约定），不静默跳过
- [ ] 磁盘边界：文档卷同步用增量方式（rsync 或等价物），避免每天整卷复制

## 边界

- 这是部署与运维工单，不动业务代码、不加业务表、不写迁移。
- 不与 `docs/DESIGN.md` 的"零外部系统集成"（D16）冲突：备份是本地卷，不引入外部服务。
- 若实现选择宿主机脚本而不是 Compose 服务，必须在 README 与票据实现说明里写明理由，并同样满足保留期、开关、可恢复性验证三条。
